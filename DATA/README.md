## 🔴 크리티컬 패스 — 추가 CSV 5개

주문·반품 데이터는 [`datasets/product_return_dataset_2000.csv`](../datasets/product_return_dataset_2000.csv)에 **이미 있습니다** (주문 2,000건 · 반품 184건 · 8상품).

문제는 **수량·가격·원가 열이 없다**는 것입니다. 그래서 4개 필수 기능 중 **반품 1개만** 돌아갑니다.

| 추가할 파일 | 없으면 막히는 기능 | 기다리는 사람 |
|---|---|---|
| `products.csv` | 정산 수익 (가격·원가), 재고·발주 (리드타임·MOQ) | 태연 |
| `purchase_orders.csv` | **불량률 전체**, 재고 (양품 입고 수량) | 태연 |
| `defects.csv` | 불량률 유형 비중 | 태연, 서영(교차 대조) |
| `suppliers.csv` | 불량률 거래처 비교 | 태연 |
| `costs.csv` | 정산 수익 (수수료·광고비·배송비·반품 처리비) | 태연 |

**이것부터 끝내고 다른 작업을 하지 않습니다.** 열 정의는 [`dictionary.md` §2](./dictionary.md)에 있습니다.

> 서영·예나의 AI 작업은 이걸 기다리지 않습니다 (반품 자유 서술이 이미 있음). 막히는 건 태연의 불량률·재고·정산 계산입니다.

## 추가 CSV 구성 기준

주문 데이터에 맞춰 만들어야 합니다.

| 항목 | 기준 |
|---|---|
| `product_id` | **P001 ~ P008** — 주문 데이터와 정확히 일치 |
| 상품명·카테고리 | 주문 데이터와 동일하게 (`와이드 데님 팬츠`, `하의/치마` 등) |
| 양품 입고 누적 | **각 상품의 주문 수보다 많게.** P002는 277장 이상이어야 재고가 음수가 안 됩니다 |
| 발주·입고 | 12~15건. **1건은 불량률이 이전 건 평균의 2배 이상** (급증 배지 시연) |
| 거래처 | 2~3곳. 불량률이 서로 다르게 나오도록 배분 |
| 비용 | 적어도 **1개 상품은 기여이익 음수**, **1개는 비용 항목 누락** |
| 불량 유형 | 반품의 `불량 제품`·`바느질/마감`과 같은 방향 → `SEWING` 비중을 높게 |

시연 시나리오 — **P002 와이드 데님 팬츠**(반품률 20.6%)에서 불량률 급증 발견 → 재고 소진 임박 → 불량률 반영 발주량 → AI 반품 분석 → 수익성 확인 → 조치 등록.

> 실제 고객 개인정보를 쓰지 않습니다.

## 계산 검증 기대값

샘플 데이터에 대한 **수작업 기대값**을 `expected/expected-metrics.md`에 작성합니다.
통합 단계에서 백엔드 계산 결과와 대조합니다. 상품 2~3개만으로 충분합니다.

| 지표 | 대조 대상 |
|---|---|
| 불량률 | 발주 건 2건 + 거래처 1곳 |
| 현재 재고 | 상품 2개 |
| 권장 발주량 | 상품 2개 (MOQ 올림이 적용되는 것 1개 포함) |
| 기여이익 | 상품 2개 (음수 1개 포함) |
| 반품률 | 상품 1개 |

## 지켜야 할 것

- CSV는 **UTF-8**, 첫 행은 헤더, 열 이름은 `dictionary.md`와 **정확히 일치**
- 열 이름 매핑 UI를 만들지 않으므로 **이 열 이름이 곧 계약**입니다
- 🔴 **불량률 분모는 `inspected_qty`(검수 수량)로 통일**합니다
- 🔴 기존 주문 CSV에 **UTF-8 BOM**이 있습니다. 추가 파일은 BOM 없이 저장하고, 적재는 어느 쪽이든 `utf-8-sig`로 읽습니다
- ID는 문자열 (`P001` — 엑셀에서 `001`이 `1`로 깨지지 않게 주의)
- 열거형은 `enums.json`의 영문 코드로 작성. 한글 라벨을 CSV에 넣지 않습니다
- 불리언은 `TRUE` / `FALSE` 대문자
- **주문 1건 = 1장**으로 간주합니다. 주문 데이터에 수량 열이 없기 때문입니다
