# 데이터 사전

**소유자:** 시환 · 🔴 크리티컬 패스

CSV는 **UTF-8**, 첫 행은 헤더, 열 이름은 아래와 **정확히 일치**해야 합니다.
열 이름 매핑 UI를 만들지 않으므로 **이 이름이 곧 계약**입니다.

공통: 날짜 `YYYY-MM-DD` · 금액 정수(원) · 비율 0~100 · ID 문자열 · 불리언 `TRUE`/`FALSE` · 열거형은 [`enums.json`](./enums.json)

> 🔴 **UTF-8 BOM 주의.** 엑셀에서 저장한 CSV에는 BOM(`U+FEFF`)이 붙습니다. 적재할 때 반드시 `utf-8-sig`로 읽으세요.
> 그냥 `utf-8`로 읽으면 첫 열 이름이 `date`가 아니라 `﻿date`가 되어 전부 어긋납니다.
> ```python
> csv.DictReader(open(path, encoding="utf-8-sig"))
> ```

# 1. 이미 확보된 데이터

## `datasets/product_return_dataset_2000.csv` — 주문 · 반품 ✅

**주문 1건 = 1행.** 판매와 반품이 한 파일에 들어 있습니다.

| 열 | 자료형 | 필수 | 설명 |
|---|---|---|---|
| `date` | 날짜 | ✅ | 주문일 |
| `product_id` | 문자열 | ✅ | `P001` 형식. 전체 데이터의 연결 기준 |
| `product_name` | 문자열 | ✅ | 상품명 |
| `category` | 문자열 | ✅ | `아우터` / `하의/치마` 등 |
| `order_id` | 문자열 | ✅ | `P004-20260422-0001` 형식 |
| `size` | 문자열 | ✅ | `M` / `L` / `XL` |
| `color` | 문자열 | ✅ | `Black` / `Navy` / `Brown` 등 8종 |
| `is_returned` | 정수 | ✅ | `0` / `1` |
| `return_type_code` | 문자열 | ✅ | **한글 라벨.** 미반품이면 `NA` |
| `return_detail_text` | 문자열 | ✅ | 자유 서술. 미반품이면 `NA`. **AI 분석 입력** |

**현황**

| 항목 | 값 |
|---|---|
| 행 수 | 2,000 주문 |
| 기간 | 2026-01-10 ~ 2026-10-24 (288일) |
| 상품 | 8종 (P001 ~ P008) |
| 반품 | 184건 = **9.2%** |
| 최근 14일 | 105건 → 일평균 판매량 산출 가능 |

**상품별 반품률**

| 상품 | 주문 | 반품 | 반품률 |
|---|---|---|---|
| P002 와이드 데님 팬츠 | 277 | 57 | **20.6%** ← 시연 주인공 |
| P004 크롭 니트 가디건 | 240 | 41 | 17.1% |
| P008 기모 후드 집업 | 235 | 37 | 15.7% |
| P001 오버핏 울 코트 | 235 | 12 | 5.1% |
| P005 플리츠 롱스커트 | 264 | 13 | 4.9% |
| P003 패딩 베스트 | 243 | 9 | 3.7% |
| P006 루즈핏 스웨트셔츠 | 247 | 9 | 3.6% |
| P007 심플 로고 맨투맨 | 259 | 6 | 2.3% |

**적재 시 처리할 것**

1. 🔴 `utf-8-sig`로 읽기 (BOM)
2. `return_detail_text`가 **홑따옴표로 감싸져** 있습니다 (`'지퍼 윗부분이 뻑뻑해서...'`) → 양쪽 `'` 제거
3. `return_type_code`가 **한글 라벨**입니다 → [`enums.json`](./enums.json)의 `source_label`로 영문 코드 변환 ([CONVENTIONS §9](../CONVENTIONS.md))
4. 미반품 행의 `return_type_code`·`return_detail_text`는 문자열 `"NA"`입니다 → `null`로 변환 (0이 아님)
5. **수량 열이 없습니다.** 주문 1건 = **1장**으로 간주합니다

**이 데이터로 되는 것**

| 기능 | 가능 여부 |
|---|---|
| 반품 원인 분석 (AI) | ✅ `return_detail_text` 184건 |
| 반품률 | ✅ 건수 기준 |
| 일평균 판매량 | ✅ 주문 수 기준 |
| 사이즈·색상별 분석 (확장) | ✅ `size`·`color` 있음 |

## purchase_orders.csv — 발주 · 입고 검수

| 열 | 자료형 | 필수 | 단위 | 설명 |
|---|---|---|---|---|
| `po_id` | 문자열 | ✅ | — | `PO2026-0312-01` 형식 |
| `product_id` | 문자열 | ✅ | — | products 참조 |
| `supplier_id` | 문자열 | ✅ | — | suppliers 참조 |
| `ordered_at` | 날짜 | ✅ | — | 발주일 |
| `received_at` | 날짜 | | — | 입고일. 미입고면 비움 |
| `ordered_qty` | 정수 | ✅ | 장 | 발주 수량 |

> 🔴 `inspected_qty`가 불량률의 분모입니다. 전수 검수가 아니면 `received_qty`와 다를 수 있고, 그때는 표본 수로 함께 표시합니다.

>
> **양품 입고 누적이 주문 수보다 많아야 합니다.** 재고 = 양품 입고 − 주문 수 + 재판매 가능 반품이므로, P002는 최소 277장 이상 입고되어 있어야 재고가 음수가 되지 않습니다.
> **1건은 불량률이 이전 건 평균의 2배 이상**이 되게 만드세요 (급증 배지 시연용). P002를 쓰면 반품 20.6%와 같은 상품에서 품질 문제가 겹쳐 시나리오가 자연스럽습니다.

# 3. 업로드 검증 규칙

| # | 규칙 | 위반 시 |
|---|---|---|
| 1 | 필수 열이 전부 존재 | 400 `VALIDATION_FAILED` — 파일 전체 거부 |
| 2 | 필수 값이 비어 있지 않음 | 해당 행 오류 보고, 나머지 적재 |
| 3 | 수량·금액이 0 이상 정수 | 해당 행 오류 보고 |
| 4 | 비율이 0~100 | 해당 행 오류 보고 |
| 5 | 날짜가 `YYYY-MM-DD` | 해당 행 오류 보고 |
| 6 | 열거형 값이 `enums.json`에 존재 (`source_label` 포함) | 해당 행 오류 보고 |
| 7 | 참조 ID가 실제로 존재 | 해당 행 오류 보고 |
| 8 | `defect_qty` ≤ `inspected_qty` ≤ `received_qty` ≤ `ordered_qty` | 해당 행 오류 보고 |
| 9 | `defects.csv` 합계 = `purchase_orders.defect_qty` | 경고 (적재는 진행) |
| 10 | `po_id`·`order_id` 중복 없음 | 해당 행 오류 보고 |
| 11 | `is_returned=1`이면 `return_type_code` ≠ `NA` | 경고 |
| 12 | 주문 데이터의 `product_id`가 `products.csv`에 모두 존재 | 해당 행 오류 보고 |

오류 응답 형식은 [`CONVENTIONS.md §10`](../CONVENTIONS.md)을 따릅니다.
