# FE — 프론트엔드 · UI

**담당:** 윤지 (보조: 예나 — 반품 분석 화면) · **스택:** React + Vite

화면 5개와 공통 컴포넌트가 들어갑니다. 백엔드를 기다리지 않고 `src/mocks/*.json`으로 개발을 시작합니다.

## 폴더

```
FE/
├── src/
│   ├── pages/        화면 5개
│   ├── components/   공통 컴포넌트 (먼저 만들 것)
│   ├── api/          API 클라이언트 — mock ↔ 실서버 전환
│   └── mocks/        mock 응답 JSON (태연 제공)
└── public/
```

## 화면

| 화면 | 담당 | 쓰는 API | 핵심 요소 |
|---|---|---|---|
| 홈 대시보드 | 윤지 | `GET /api/dashboard` | 4개 영역 요약 카드 |
| 불량률 | 윤지 | `GET /api/quality/defect-rates` | 거래처·상품별 표(표본 수 병기), 불량 유형 비중 막대, **급증 배지** |
| 재고·발주 | 윤지 | `GET /api/inventory` · `/api/inventory/reorder` | 재고 소진 예상일, **권장 발주량 + 산출 근거 접기/펼치기** |
| 수익성 | 윤지 | `GET /api/profit` | 상품별 수익성 표, 비용 구성 비중, **기여이익 음수 강조** |
| 반품 분석 + 조치 | **예나** | `GET /api/returns/rates` · `POST /api/returns/analyze` · `/api/tasks` | AI 네 블록 표시, 원문 근거, 조치 등록 |

## 공통 컴포넌트 — 먼저 만들 것

화면이 5개이므로 컴포넌트를 먼저 만들고 재사용하는 것이 가장 중요합니다.

| 컴포넌트 | 용도 |
|---|---|
| `MetricCard` | 대시보드 요약 카드 |
| `DataTable` | 표 (정렬·강조 행) |
| `Badge` | 급증 / 발주 경과 / 적자 / 표본 부족 |
| `BarShare` | 비중 막대 (불량 유형, 비용 구성) |
| `EvidenceBox` | **산출 근거** — `inputs` + `formula`를 접었다 펼치기 |
| `AIBlock` | AI 네 블록(관측된 사실 / 가능한 원인 / 추가 확인 / 개선 체크리스트) |
| `EmptyState` | 로딩 / 데이터 없음 / 오류 / 산출 불가 |
| `Num` | 숫자 포맷 — 금액 `1,069,200원`, 비율 `8.0%`, 수량 `184장` |

## 지켜야 할 것

- 응답 키는 `snake_case` 그대로 씁니다. 변환 레이어를 만들지 않습니다.
- **비율은 이미 0~100입니다.** `_pct` 값에 `× 100`을 하지 않습니다.
- **`inputs`·`formula`를 반드시 화면에 노출합니다.** 숫자만 보여주면 근거를 알 수 없습니다.
- **계산된 수치와 AI 추정을 시각적으로 구분합니다.** 같은 스타일로 섞지 않습니다.
- `null`은 "0"이 아니라 `notes`의 문구로 표시합니다.
- 디자인 시안 작업은 생략하고 차트 라이브러리 기본 스타일을 씁니다.
- 🔴 API 키를 프론트엔드 코드에 넣지 않습니다. `VITE_` 변수는 브라우저에 노출됩니다.

## 실행

```bash
cd FE
npm install
npm run dev          # http://localhost:5173
```

mock ↔ 실서버 전환은 `src/api/`에서 한 곳으로 처리합니다. 통합 때 이 한 줄만 바꾸면 되게 만드세요.
